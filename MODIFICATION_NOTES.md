# Dyn7 reorganization notes

This tree keeps Dyn3D-SGA as the main method and adds the uploaded Spherical-Steering implementation as a separate comparison method.

## Layout

- `method/dyn3d_sga/`: Dyn3D-SGA, including the generic-task pipeline restored from dyn6.
- `method/spherical_steering/`: Spherical-Steering implementation copied from the uploaded Spherical-Steering archive, including TruthfulQA and generic entrypoints.
- `script/<method>/<LLAMA|QWEN>/`: runnable method scripts.
- `hyperparams/<method>/<LLAMA|QWEN>/`: model-specific parameters; Dyn3D shared training defaults live in `hyperparams/dyn3d_sga/common.sh`.
- `results/experiment/<experiment>/`: all experiment plots/CSVs/JSONs and ablation checkpoints/evaluations/summaries.
- `results/generic/<dataset>/<method>/`: generic-task evaluation outputs.

## steering_vector_ablation

The uploaded `vector_utils.py` is preserved. The experiment compares:

1. linear + exact raw answer-pair vector;
2. linear + shared arithmetic mean vector;
3. spherical + exact raw answer-pair vector;
4. spherical + shared arithmetic mean vector.

For spherical steering, a vector `v` is mapped to antipodal prototypes `mu_T = normalize(v)` and `mu_H = -mu_T`. Every scored choice receives the intervention. Pair-specific MC1 scores the truthful/false members of every pair with the same pair vector and requires the truthful answer to win every pairwise comparison.

`prepare_fold_features.py` adds the fold metadata required by the uploaded `vector_utils.py` to base `*_dynSVD_pairs.npz` files. `run.sh` can generate those base files first with `RUN_EXTRACT=1`.

## Validation

Run:

```bash
python tools/validate_dyn3d_setup.py
python -m unittest experiments.steering_vector_ablation.test_vector_utils -v
```

The validator checks Python syntax, `bash -n` for every shell script, required restored files, hyperparameter layout, stale executable paths, result-file hygiene, and method entrypoints. Full model inference still requires the configured local model/data dependencies.
